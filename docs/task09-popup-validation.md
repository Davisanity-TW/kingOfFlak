# 工單 09 彈出視窗追加驗證

## 交付範圍

依 [追加規劃](task09-popup-plan.md) 實作開始前與結算後入口，以原生 `dialog` 覆蓋主畫面。返回、Esc、背景點擊關閉並還原焦點，視窗內阻擋底層起飛與移動；結算視窗提供再飛一次。首次查看無須暱稱，不提交成績，也不顯示本局摘要。

死亡自動提交一次並讀榜，僅點擊時開視窗，每次開啟／重讀更新榜單；提交中開啟等待同一次提交完成或逾時，不重送。進行中的讀榜共用同一請求，停用重讀按鈕，避免連點並行。關閉不取消提交，回應不重開視窗；有效重玩清空畫面與本局狀態，以世代編號隔離舊回應。

本局摘要固定原名、模式及秒數；修改下一局暱稱不改舊摘要。唯一局次、原名、模式、整數成績全部符合才標示本局列與新入榜；最新榜未含本局或讀榜失敗時移除標記。回應遺失後若榜內確認本局，記住已收錄證據；未找到則維持不確定，不誤稱未入榜。已確認收錄而被擠出時顯示未入前 50 名。

使用者於實作中指定移除 X 關閉鍵；新入榜時另在結算存活時間下方顯示紅色小字 `New Record`，以 1.6 秒淡入淡出閃爍，減少動態效果偏好下保持靜態。讀榜更新、失敗與重玩時沿用入榜標記狀態清除。

排行榜讀取與成績保留上限改為 50；同一交易裁切榜外成績，未入榜回覆 `stored: false`，既有資料由新增遷移裁切。未入榜與被擠出資料不留歷史；同局防重複只對仍保留的局次有效。維持排序、遊戲難度與碰撞規則；遠端資料沿用既有驗證及 `textContent`，不新增依賴。

瀏覽器與真實 API 測試依序執行，避免遊戲因失焦暫停。API 測試啟動獨立本機 Worker／D1，以電腦與觸控手機兩個獨立 Chrome 環境驗證共同榜單，不寫入正式資料庫。

## 玩家驗收

依 README 啟動本機 API 與 Vite，開啟 [本機遊戲](http://127.0.0.1:5174/)：

1. 空白暱稱按「查看排行榜」，應正常開啟；返回、Esc、點背景皆回原畫面。視窗內點表格不關閉，不能操作底層開始或搖桿。
2. 完成一局，不自動彈出；「修改暱稱」下方提供排行榜入口。本局進入前 50 名時入口及對應列顯示新入榜，摘要保留原名與秒數；同名其他局不標為本局。
3. 未入前 50 名時應明示「未收錄」，但保留本局暱稱與秒數。關閉再開、手動重讀取得最新榜；改下一局暱稱後查看，摘要仍是剛完成的一局。按「再飛一次」關閉並清空本局顯示，重新倒數，保留目前有效暱稱及模式。
4. 手機橫放捲動完整長榜與視窗，確認能到達返回及重玩；關閉 API 再讀應顯示錯誤、清空表格與入榜標記，仍能返回或重玩。

## 驗證結果與邊界

2026-11-06：30 項單元測試、8 項真正 Worker／D1 測試通過；Chrome／Playwright WebKit 共 66 個案例完成驗證。完整回歸先通過 64 項，兩個舊提示文字斷言同步為「本局曾收錄」後，指定重跑兩項皆通過；沒有未解決的失敗。型別、格式、差異檢查與正式 API 設定的建置通過，產物確認使用正式 API、不含本機服務 URL。

API 測試涵蓋新增／同局競爭、同分排序、50 筆上限、榜外提交 `stored: false`、資料表實際維持 50 筆、舊資料裁切遷移、每分鐘 20 次限流及重啟持久性。真實電腦與觸控手機兩個獨立環境讀到相同共同榜，且各只強調自己的本局並顯示 New Record。

瀏覽器覆蓋所有返回方式、焦點限制、草稿保留、每次開啟新榜、提交中關閉不重開、重玩隔離、回應遺失確認、同名不同局、被擠出、榜外未收錄、錯誤／逾時、50 列捲動及紅色／減少動態效果。已檢查 `test-results/leaderboard-desktop.png`、`test-results/leaderboard-mobile.png` 及 `test-results/new-record.png`；截圖由測試產生，不納入 Git。
