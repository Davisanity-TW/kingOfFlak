# 手機與電腦排行榜分開

2026-11-06 工單 09 追加修訂，取代原本兩種模式共用總榜及顯示名稱附加後綴的規格。

## 玩家行為

- 開始前與結算後沿用原本排行榜入口，彈出視窗增加「手機／電腦」切換按鈕，預設目前遊戲模式，各自最多顯示 50 名。
- 兩個榜各自排名與裁切；同一玩家可有多局，不合併同名。排序仍為十分之一秒降冪、完整伺服器時間升冪、紀錄 ID 升冪。
- 暱稱直接顯示原名，不再由系統加上 `_mb`／`_pc`。玩家自行輸入的相同字尾完整保留；既有暱稱記憶不變。
- 上傳依當局固定的 `mode` 決定資料庫，切換查看其他榜不更改遊戲模式、不重新提交。快速切換時，晚到的另一榜回應不能覆蓋目前畫面。
- 本局摘要標明手機或電腦；本局列只在自己的榜單強調。切到另一榜不會把本局誤判成未入榜，入口新入榜與紅色 `New Record` 仍依當局模式判定。
- 返回、Esc、點背景、再飛一次、5 秒逾時及不補傳規則保持原行為。每個模式只保留榜內資料，榜外不留歷史。

## API 與資料庫

`GET /scores?mode=mb` 查手機榜，`GET /scores?mode=pc` 查電腦榜；省略 `mode` 預設電腦，以相容舊網址；其他值回覆 `400 invalid_mode`。前端驗證回傳紀錄必須符合所選模式。`POST /scores` 欄位不變，由 `mode` 選擇資料庫；去重與每 IP 每分鐘 20 次新局嘗試限制各自在該模式資料庫執行。

本機 `npm run api:migrate:local` 同時建立兩個資料庫。各資料庫使用相同的 `server/migrations/` 結構；正式與隔離環境不可共用綁定。

## 舊資料搬移

舊畫面的 `_mb`／`_pc` 是前端顯示時加上的字尾；資料庫已獨立儲存原始 `nickname` 與 `mode`，因此依 `mode` 分流，不裁切或猜測原名。

1. 建立並初始化兩個新正式 D1，從舊庫匯出完整紀錄。首次快照共有 50 筆，電腦 18 筆、手機 32 筆。
2. `server/migrate-scores.ts` 的 `splitScoreSql` 驗證資料後產生兩份 SQL，保留原名、局次 UUID、紀錄 ID、整數分數與完整收錄時間；同一局次重跑不新增重複資料，各榜按原排序保留前 50 名。
3. 先匯入新庫，再部署新 Worker；切換後再次唯讀匯出舊庫，確認與首次快照一致。逐欄比較正式 API 與快照：電腦 18 筆、手機 32 筆，原名、局次、ID、分數與時間全部保留，無需再次寫入或裁切。匯出資料與暫存 SQL 位於已忽略的 `.wrangler/board-split/`，不納入 Git。
4. 舊正式庫 `king-of-flak-scores`（`0b034940-ad82-42c4-9571-5af55548abe5`）保留作搬移備份，不再由新版 Worker 綁定或寫入。這是舊榜前 50 名快照，已經被舊政策移除的榜外成績無法恢復。

資料庫 ID 是公開資源識別碼，不是存取憑證；遷移與部署使用本機既有 Wrangler 登入，不提供玩家 SQL 或刪除接口。
