# 工單 09 驗證紀錄

## 實作範圍

- 結算資料由死亡當下固定，單次提交後讀榜；每個請求 5 秒逾時。榜單列數上限 20，空陣列顯示「尚無紀錄」。
- `src/result-board.ts` 管理上傳與讀榜提示；世代編號隔離舊局回應，重玩或改名後不覆蓋新畫面。單次讀榜期間停用重試，不建立離線佇列、不自動補傳。
- `src/leaderboard.ts` 區分 HTTP 服務錯誤，驗證遠端欄位、分數與時間，限制 20 列；文字一律使用 `textContent` 呈現。日期以 `Asia/Taipei` 格式化，不依觀看者時區。
- 表格有標題、欄位標頭、可聚焦捲動區與狀態提示；重玩在榜單之前。手機側欄與表格可捲動，不把網路進度當作遊戲暫停。

## 可重現檢查

```sh
npm run test:unit
npm run test:api
npm run test:e2e
npm run build
npm run format:check
```

`tests/result-board.spec.ts` 對真實遊戲操作，攔截 API 驗證成功、空榜、21 筆截為 20 筆、台北跨日、上傳拒絕、回應遺失、上傳及讀榜逾時、離線及服務故障、只讀重試、晚到的上傳及讀榜回應、未設定服務，以及手機長榜捲動與重玩。這些 API 攔截測試不代表真實服務或實機驗收。

`tests/api.test.ts` 使用真正 Worker／D1 與兩個獨立 Chrome 環境（電腦、640×360 觸控手機模擬），各完成一局並驗證畫面表格一致。瀏覽器測試須依序執行，避免互搶焦點；修改程式或 Vite 設定也會重載頁面，執行期間保持不變。

## 發布與外部驗收邊界

工單 08 正式網站已於 `8e72e13` 發布；本輪工單 09 尚未推送或部署。正式 API 與隔離測試 API 沿用 [服務設定](leaderboard-service.md)，本輪不變更資料庫結構。公開發布後，須以兩個獨立瀏覽器驗證共同榜單，並補手機／Safari 實機操作紀錄；未執行前不得標成已發布驗收完成。

本輪不重跑工單 05 的 10 分鐘壓測；不修改彈幕、碰撞、暫停與難度規則。免費服務額度與休閒榜可信度限制沿用工單 08。
