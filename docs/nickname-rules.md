# 暱稱規則與工單 08 交接

工單 07 的共用實作位於 `src/nickname.ts`。後續服務端須沿用並自行執行相同驗證，不能信任前端已驗證或用戶端提供的後綴。

- `parseNickname` 接受字串，先 `trim()`，以 Unicode 字碼點計算長度 1–12；正規表示式為 `^[\p{Script=Han}A-Za-z0-9_]+$`（Unicode 模式）。不接受內部空白、表情符號、全形英數或其他符號；無效回傳 `null`，有效回傳去除前後空白的原名。
- `createRoundIdentity` 將有效原名與固定的 `mobile` 模式組成不可變物件，包含 `nickname`、`mobile`、`displayName`。`displayName` 直接等於原名，不附加 `_pc`／`_mb`。原名 `Ace_pc` 仍顯示 `Ace_pc`；不移除玩家原有字尾。模式沿用頁面載入時 `pointer: coarse` 的遊戲判斷。
- 儲存鍵為 `king-of-flak.nickname`，JSON 格式為 `{"version":1,"nickname":"飛行員"}`，只保存原名。只有有效開始才寫入；重新載入只預填。`readSavedNickname` 忽略未知版本、損壞 JSON、缺欄位及無效原名。
- `localStorage` 讀寫由入口捕捉例外，顯示「無法記住暱稱，仍可正常遊玩。」；寫入失敗不清掉原紀錄，也不阻擋當局。
- 開始按鈕、表單 Enter、再飛一次及搖桿開始共用入口；輸入時方向鍵留給文字編輯。結算改名只影響下一局，取消還原上一局原名。每次有效開始建立新的固定身分。

進場提示暱稱與成績將公開顯示於對應裝置排行榜；目前已接通成績服務與彈出視窗，手機／電腦各自前 50 名。模式獨立記錄，不靠暱稱字尾辨識，不可把此處固定物件當作伺服器認證。

`npm run test:unit` 驗證字碼點邊界、允許字元、快取與不可變身分；`npm run test:e2e` 驗證 Chrome／WebKit 首次輸入、重載、重玩、儲存例外與手機模擬。真實軟鍵盤不能由縮小視窗測試取代，仍需玩家在實機橫放驗收。
